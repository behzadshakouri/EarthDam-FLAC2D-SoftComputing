# Task 3: Multi-Output Seismic Response Prediction

This folder contains the reproducible MATLAB workflow for predicting 70
spatially distributed seismic responses of an earth dam using Fast
Multi-Output Relevance Vector Regression (FMRVR). Task 3 uses 150 synthetic
ground-motion simulations and is methodologically independent of the Task 2
Intensifying Artificial Acceleration (IAA) study.

## Canonical study design

| Item | Task 3 definition |
|---|---|
| Numerical realizations | 150 synthetic ground motions |
| Development/testing | Ten deterministic 105/45 record-level outer splits |
| Locations | P1--P10 |
| Responses | Xdisp, Ydisp, Sxx, Syy, Ppore, ssi, vsi |
| Output order | P1R1--P1R7, ..., P10R1--P10R7 |
| Target matrix | 15,000 by 70 cumulative-envelope samples (100 per record) |
| Primary surrogate | Ten ridge-free point-wise FMRVR models, seven coupled outputs each |
| Development selection | Three-fold record-level selection of each point's response transform |

The raw histories are converted to positive nondecreasing response envelopes
before a common simulation-level loss-of-validity boundary calibrated from the
FLAC2D sentinel pattern. Displacement and strain envelopes use cumulative
absolute response; stress and pore-pressure envelopes use cumulative absolute
change from the initial static state. One hundred native-duration samples are
retained per record. The sentinel and subsequent runaway values never enter
the targets. The earlier 150-by-70 scalar peak formulation is retained as a
documented benchmark, not the accepted prediction task.

## Quick start

1. Copy `config/task3_local_paths.m.example` to
   `config/task3_local_paths.m`, set the private `Task3Data.mat` path, and
   select external roots for full results, intermediate analysis products,
   and generated figures.
2. In MATLAB R2020a or newer, run:

   ```matlab
   cd task3_synthetic_ground_motions
   report = run_task3_validated_workflow("full");
   ```

The validated runner executes the entire accepted paper workflow: preparation,
common-onset failure screening, 33-predictor cumulative-path construction,
record-separated nested validation, ridge-free point-wise FMRVR fitting, figures,
tables, and artifact checks. It
creates local products under the machine-specific output roots configured in
`config/task3_local_paths.m`. Compact reviewed CSV evidence is kept in
`reference_results`; raw and intermediate MAT files are not intended
for GitHub. See `docs/PIPELINE.md` for the exact stages and faster artifact-only
and verification modes.

The extended analysis functions are under `analysis`. The primary final
analysis is generated by `run_task3_compact_pointwise_fmrvr_validation.m` and is
orchestrated by the top-level validated runner. Supporting scalar-demand,
detector, feature, modal-period, and rejected-refinement evidence is mapped in
`docs/MANUSCRIPT_EVIDENCE_MAP.md`.

The manuscript source, compiled paper, figures, tables, and original Overleaf
export are maintained in the separate paper archive and are not part of this
repository, consistent with Tasks 1 and 2.

## Data contract

The private MAT-file must contain a scalar structure named `Task3`:

- `Task3.Inputs.InputsMatrix(1:150)` with `time`, `accel`, and `PGA`;
- `Task3.Outputs.P1` through `P10`;
- each point contains `R1` through `R7` as 150-by-1 cell arrays of histories.

See `docs/RAW_DATA_CONTRACT.md` and `data/README.md` for details.

## Leakage controls

- Every outer split is performed by ground-motion record; all 100 time samples
  and all 70 outputs from a simulation remain together.
- Predictor and target transformations are fitted on the 105 development
  records only and applied unchanged to the 45 held-out records.
- All robust input transformations, output transformations, and FMRVR
  parameters are fitted without outer-test targets.
- Each point's target transformation is selected in three development-record
  folds using nRMSE.
- Constant development outputs are restored by the development mean and
  excluded from variable-output accuracy summaries.

## Third-party implementation

The solver in `third_party/fmrvr_ha/` is the original file distributed
by Youngmin Ha under the included BSD-style license. The Gaussian design-matrix
implementation and all project-specific wrappers are maintained separately
under `src/`.

Production uses `src/modeling/fmrvr_task3.m`, a local copy with empty-model
coefficient outputs initialized before the EM loop. This handles the source
solver's zero-relevance-basis early exit without undefined outputs. The
original solver remains unchanged. The training wrapper records the output
rank and transformation; these adaptations must be disclosed with results.

Please cite:

> Ha, Y., & Zhang, H. (2019). Fast multi-output relevance vector regression.
> *Economic Modelling*, 81, 217--230.
> https://doi.org/10.1016/j.econmod.2019.04.007

The journal PDF is not distributed in this repository.

## Current status

The precommit scalar-demand implementation has been audited against the private
150-motion database and retained as a strict benchmark. Its best nested mean
$R^2$ was 0.6743 for failure-aware FMRVR and 0.6808 for matched ridge.

The accepted response-evolution workflow uses 100 equally weighted
native-duration samples per record, 16 record descriptors, and 17 cumulative
time-varying excitation descriptors. All rows belonging to a ground motion stay
in the same outer partition. Across ten stratified 105/45 record splits, ten
ridge-free point-wise FMRVR models reach mean $R^2=0.8574$ (SD 0.0135), mean
nRMSE 0.0450, mean nMAE 0.0257, and mean $a_{10}=0.3648$. On an average split, approximately 57 of
67 nonconstant outputs exceed $R^2=0.8$ and 27 exceed $R^2=0.9$. Compact
reviewed outputs are under
`reference_results`; large predictions and models remain ignored.

This directory is still working-tree material. Per the project release plan,
no commit should be created until the manuscript has been submitted and the
remaining provenance and author checks in `docs/RELEASE_CHECKLIST.md` are
resolved.
